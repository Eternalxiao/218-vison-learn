# YOLO11 数据准备：从现场画面到可训练数据集

## 写在最前面的劝谏

数据是整个训练中最重要的一步，因为你基本上不会使用除了 YOLO 以外的第二个架构，一般不会学习到如何量化微调模型，所以数据准备可以说是唯一一个可控的变量，同时优质的数据对于最终的模型有着决定性的作用，这里引用一段 Ted Sanders 在 OpenAI Cookbook 中发布的内容，原话如下：

```txt
“It's becoming awfully clear to me that these models are truly approximating their datasets to an incredible degree... What this manifests as is – trained on the same dataset for long enough, pretty much every model with enough weights and training time converges to the same point. This is a surprising observation! It implies that model behavior is not determined by architecture, hyperparameters, or optimizer choices. It's determined by your dataset, nothing else. Everything else is a means to an end in efficiently delivery compute to approximating that dataset.”
```

同时腾讯模型早期遇到的瓶颈，很大的原因也是数据质量、清洗和策略选择上出现了偏差（感兴趣的同学可以查询了解当时的历史故事）。讲这么多就是为了提醒大家，如果决定使用训练模型的方式解决问题，那么一定要耐心的准备好优质的数据，即使这个过程是最枯燥繁琐的。

数据准备的目标不是尽量堆图片，而是让训练集覆盖模型需要学习的变化，让验证集真正代表“没有见过的新场景”。如果同一段视频的相邻帧同时出现在训练集和验证集，指标可能很好看，却不能回答模型换一个角度、背景或光照后是否仍然有效。

本篇按这条主线展开：视频抽帧 → EasyData 物体检测标注 → Pascal VOC 导出 → YOLO 标签 → 检查 → 划分。平台界面会更新，因此文中把稳定的概念、输入输出和验收方法写清楚，按钮位置以实际页面为准。

## 1. 先写标注规范，再开始采图

在采集前先回答四个问题：

1. 模型需要检测什么对象？每个类别的名称是什么？
2. 哪些相似对象不属于目标，必须作为负样本出现？
3. 遮挡、截断、模糊到什么程度仍然画框？
4. 一个目标由多个零件组成时，框整体还是框零件？

这些规则要写成几张正反例。多人标注时，所有人使用同一份规则；单人标注时，它也能防止自己前后标准变化。

类别 ID 由顺序决定。配套的 [`classes.txt`](../../配套资源/示例代码/yolo11/classes.txt) 一行一个真实目标类别，第 1 行对应 ID 0。训练用的 [`data.yaml`](../../配套资源/示例代码/yolo11/data.yaml) 必须保持相同顺序。

负样本不是一个需要画框的 `background` 类。没有任何目标的图片保留下来，并配一个内容为空的 `.txt` 标签即可。这样模型能看到真实背景，却不会被要求寻找一个叫“背景”的物体。

## 2. 采集的是场景变化，不是连续帧数量

建议先列一张采集清单，再逐项拍摄：

- 距离：近、中、远，尤其包含现场最小目标。
- 视角：相机实际会出现的俯仰、旋转和边缘位置。
- 光照：正常、偏暗、偏亮、局部阴影和反光。
- 背景：赛场材料、桌面纹理、线缆、手和其他容易误检的物体。
- 目标状态：完整、部分遮挡、画面边缘截断、多个目标同时出现。
- 无目标画面：部署时常见但不应产生检测框的场景。

不要为了覆盖清单制造设备上永远不会出现的条件。比如相机固定且目标方向有语义时，上下翻转图片并不代表真实变化，我们应该尽量个人拍摄出对应不同情况的照片，如果确实无法模拟全部情况可以考虑数据增强，这里推荐在EasyData的数据增强中添加对应的算子进行数据增强，并且建议对批注完的图片的进行数据增强，避免增加数据量后需要批注更多的图片。

### 从视频抽帧

先在仓库根目录进入教学脚本目录，打开 [`video2frame.py`](../../配套资源/示例代码/yolo11/video2frame.py) 把调参区改成自己的视频和输出目录，然后直接运行：

```powershell
Set-Location 配套资源\示例代码\yolo11
python video2frame.py
```

[`video2frame.py`](../../配套资源/示例代码/yolo11/video2frame.py)使用 `imencode().tofile()` 保存图片，以兼容 Windows 中文路径；所有参数集中在脚本开头的调参区，并带防覆盖检查。

- `INTERVAL = 9` 表示每 9 帧保存一张，不等于“每秒 9 张”。实际时间间隔还取决于视频 FPS。
- `WIDTH = 320`、`HEIGHT = 224` 对应本项目后续板端输入比例。若原视频比例不同，直接缩放会产生形变；应先决定裁剪、留边还是改用与部署一致的录制分辨率。
- `PREFIX` 把来源写进文件名。不同视频使用不同前缀，之后才能识别近重复帧来自哪一段镜头。

抽帧后先人工删除失焦、严重运动模糊、曝光失控和几乎完全重复的图片。提高 `INTERVAL` 只能减少重复，不能代替场景设计。

## 3. 在 EasyData 创建物体检测数据集

百度官方把 EasyData 定义为数据采集、清洗、标注和增强平台。部分账号的控制台中不能直接搜索到独立产品时，官方说明可以从 `ai.baidu.com → 开发平台 → EasyData 数据服务平台` 进入。入口或权限变化时，以[EasyData 官方文档目录](https://ai.baidu.com/ai-doc/index/EasyData)为准。

创建数据集时选择：

```text
数据类型：图片
标注类型：物体检测
标注模板：矩形框
```

然后把清理后的图片作为“未标注数据”上传。少量图片可以直接选择文件，数量较多时使用 ZIP。官方[图片数据导入说明](https://cloud.baidu.com/doc/EasyData/s/Qk9clbtuj)列出了支持的图片格式、单文件大小和压缩包要求；这些限制可能调整，不在本仓库复制成永久参数。

上传后先核对三件事：图片数量是否一致、图片方向是否正确、是否出现平台去重导致的数量变化。平台去掉完全相同的图片并不能发现所有“看起来几乎一样”的连续帧，后者仍需自己检查。

## 4. 在线标注怎样保持一致

EasyData 的[在线标注说明](https://cloud.baidu.com/doc/EasyData/s/6k9jouf9h)中，物体检测对应矩形框模板。开始标注前先创建全部标签，标签名称与 `classes.txt` 保持一致。

画框时遵守同一套规则：

- 框包含完整可见目标，尽量少带无关背景。
- 同一种遮挡程度要么都标，要么都不标，不能凭当时感觉变化。
- 目标被画面边缘截断时，框住可见部分，并在规范中说明是否保留这类样本。
- 图片中出现的每一个应检测目标都要标出；漏掉的目标会把“这里没有目标”的错误信息交给模型。
- 无目标图片不画任何框，但要保留为负样本。

每完成一批标注，就抽查小目标、密集目标、画面边缘和容易混淆的类别。不要等全部标完后才第一次审核。

## 5. 智能标注是预标注，不是自动验收

写在前面的话，其实我们一般个人的数据集集中在 2k~6k 图片之间（比赛期间也不会有太多的时间准备更多），在平台上批注的速度其实很快只是有点繁琐枯燥，自动批注的效果取决于已经批注的个数、需要批注的数量，整个自动流程其实会消耗很长的时间并且效果不尽如人意，建议个人批注 1/3 数量的数据集后在进行自动批注。

EasyData 的图像智能标注提供两条路线：

- 主动学习：先用已标数据训练底层模型，系统分轮筛选更值得人工确认的难例。
- 指定模型：复用 EasyDL/BML 或既有智能标注任务产生的模型，为相似数据生成预标注。

官方[图像智能标注说明](https://ai.baidu.com/ai-doc/EasyData/rk9jovuv4)要求在任务启动前创建完整标签并准备一部分人工框；文档列出的主动学习启动条件包括每个标签至少 10 个框、未标图片多于 100 张。平台规则可能随版本和账号调整，以任务页面实际提示为准。

推荐顺序是：

1. 人工标一批覆盖不同场景的图片，不要只标最清楚、最容易的样本。
2. 创建智能标注任务，等待系统筛选难例或生成预测框。
3. 逐张确认预标注：补漏框、删误框、改类别、收紧或放宽不一致的框。
4. 一般会总计四轮的自动批注任务，这四轮可能会浪费很多时间，但这是必要的
5. 自动批注时的难例确认一定要手动确认清楚，这直接影响最终的批注结果
6. 只有抽查确认规则稳定后，才批量确认其余结果。
7. 结束任务后再次按类别和场景抽查，保存一个新的数据集版本。

智能标注任务运行期间，官方文档提示不要随意增删标签或图片；大量修改已有框也会影响预标注效果。如果发现类别定义本身有问题，应结束任务、修正规范，再重新开始，而不是一边改变规则一边接受自动结果。

## 6. 数据增强只进入训练集

EasyData 的[数据增强说明](https://cloud.baidu.com/doc/EasyData/s/Nl3qtaklu)支持图片类任务；物体检测目前对应矩形框标注。创建增强任务时需要选择输入/输出数据集、算子以及“串行叠加”或“并行遍历”策略：

- 串行叠加：多个变换依次作用在同一张新图片上，组合过强时容易偏离真实画面。
- 并行遍历：不同算子分别从原图生成新图片，更容易判断每个算子的影响。

增强数据与原图高度相关，因此不能让原图进入训练集、增强版本进入验证集。更稳妥的顺序是：

1. 保存一份不增强的标注主版本。
2. 按视频或采集场景分组，先确定训练、验证和测试来源。
3. 只对训练来源创建增强版本；验证集和测试集保持原始分布。
4. 从增强结果中按数据来源筛选并人工审核，删除框错位或不符合现场条件的图片。

亮度、对比度、轻微模糊、噪声、小角度旋转或尺度变化是否合理，要由部署场景决定。上下翻转、极端色偏、强透视和大面积裁剪可能制造现实中不存在的样本。增强也不能修复漏标、错标或类别定义冲突。

## 7. 从 EasyData 导出后先识别格式

不同产品入口和版本的导出能力并不完全相同。EasyData 的[数据导出文档](https://cloud.baidu.com/doc/EasyData/s/jk9clc6yw)描述了导出到 BOS 后得到源文件与标注 JSON；[EasyDL 更新记录](https://ai.baidu.com/ai-doc/EASYDL/rkmokc738)还说明图像数据可导出 VOC、COCO。不要只看压缩包名字，应先打开一个标注文件确认格式。

本篇后续脚本使用 Pascal VOC：

```text
voc/
├── Images/
│   ├── scene01_0000.jpg
│   └── scene01_0001.jpg
└── Annotations/
    ├── scene01_0000.xml
    └── scene01_0001.xml
```

如果平台提供 VOC 选项，优先按这套教学流程导出。若拿到的是 JSON 或 COCO，不能把后缀改成 `.xml` 后交给脚本；应选择匹配的转换器或回到平台选择 VOC。本仓库的 [`voc_to_yolo.py`](../../配套资源/示例代码/yolo11/voc_to_yolo.py)只接受 Pascal VOC XML，这个边界是故意明确的。

## 8. 把 VOC 转成 YOLO 标签

这里有一个细节，一般情况我们会在数据集中添加一些只有纯背景无目标地图片作为负样本进行训练（理论上这样做会增强模型识别能力），但是如果将这些纯背景的图片你导入到 EasyData 中会让数据批准变得困难，同时需要注意的是默认使用 EasyData 导出的图片和标签是一一对应的，对于在 EasyData 中没有批注的照片也会导出照片，但是不会导出 VOC格式的标签，所以需要人为的添加纯背景图片的标签（标签为空，不添加会导致训练时候识别不到），仓库中的[`voc_to_yolo.py`](../../配套资源/示例代码/yolo11/voc_to_yolo.py)逻辑已经覆盖到了这一情况，但是不是开箱即用的请阅读理解代码以后在使用。

先修改 `classes.txt`，再打开 [`voc_to_yolo.py`](../../配套资源/示例代码/yolo11/voc_to_yolo.py) 确认调参区的 `IMAGES_DIR`、`ANNOTATIONS_DIR` 和 `OUTPUT_DIR`，然后直接运行：

```powershell
python voc_to_yolo.py
```

若导出目录中“没有 XML 的图片”已经逐张确认都是无目标负样本，才把调参区的 `MISSING_AS_BACKGROUND` 改为 `True`。

脚本按以下公式换算坐标：

```text
x_center = (xmin + xmax) / 2 / image_width
y_center = (ymin + ymax) / 2 / image_height
width    = (xmax - xmin) / image_width
height   = (ymax - ymin) / image_height
```

输出的每一行是：

```text
class_id x_center y_center width height
```

后四项归一化到 0～1。脚本不会移动或删除原始数据；缺失 XML 必须由使用者明确确认为负样本，遇到未知类别或越界框会停止。

## 9. 在划分前检查标签

打开 [`check_dataset.py`](../../配套资源/示例代码/yolo11/check_dataset.py)，确认调参区的 `IMAGES_DIR`、`LABELS_DIR` 指向上一步的输出目录，然后直接运行：

```powershell
python check_dataset.py
```

[`check_dataset.py`](../../配套资源/示例代码/yolo11/check_dataset.py)检查：

- 每张图片是否有同名 `.txt`，是否存在孤立标签。
- 每行是否正好包含类别 ID 和四个坐标。
- 类别 ID 是否落在 `classes.txt` 范围内。
- 归一化中心、宽高和边界是否仍在图片范围内。
- 每类框数以及空背景图片数量。

脚本通过只说明结构和数值合法，不说明框画得正确。仍需随机打开图片，把标签可视化复核。

## 10. 按来源划分，而不是让近重复帧泄漏

最终目录采用 Ultralytics 常见结构：

```text
dataset/
├── images/
│   ├── train/
│   ├── val/
│   └── test/
└── labels/
    ├── train/
    ├── val/
    └── test/
```

若图片彼此独立，可用固定随机种子复制划分。打开 [`prepare_dataset.py`](../../配套资源/示例代码/yolo11/prepare_dataset.py) 确认调参区的 `OUTPUT_DIR`、`TRAIN_RATIO`、`VAL_RATIO`、`TEST_RATIO` 和 `SEED`，然后直接运行：

```powershell
python prepare_dataset.py
```

[`prepare_dataset.py`](../../配套资源/示例代码/yolo11/prepare_dataset.py)不会移动源文件，输出目录已有数据时会停止。它按“图片”随机划分，不认识视频来源，因此连续视频帧不能直接交给它随机分配。先按 `scene01`、`scene02` 这类前缀把整段来源分到同一子集，再复制到对应目录；或者在抽帧前就把不同视频指定为训练、验证和测试来源。

- `train` 用来更新参数，可以包含合理的数据增强。
- `val` 用来选配置和分析错误，不能混入训练增强副本。
- `test` 在方案基本确定后使用，不应反复看着测试结果调参。

数据量很小时，不要机械坚持某个比例。先保证每个子集至少覆盖关键类别和场景，再记录实际数量。

## 11. 最后核对 data.yaml

教学示例的 [`data.yaml`](../../配套资源/示例代码/yolo11/data.yaml)是：

```yaml
path: dataset
train: images/train
val: images/val
test: images/testa

names:
  0: target
```

修改 `names` 时同步修改 `classes.txt`。`background` 不加入 `names`。训练前确认工作目录是 `配套资源\示例代码\yolo11`，这样相对路径 `dataset` 才指向刚才生成的目录。

## 完成检查

- [ ] 抽帧文件名能追溯到原视频或场景。
- [ ] 智能标注结果经过人工确认，不把预标注直接当真值。
- [ ] 数据增强只来自训练来源，验证和测试没有增强副本。
- [ ] `classes.txt`、YOLO 标签 ID 和 `data.yaml` 顺序一致。
- [ ] 结构检查通过，并人工可视化复核过一批正样本、负样本和边界样本。
- [ ] 同一段连续镜头没有被随机拆到 train、val、test 多个子集中。
