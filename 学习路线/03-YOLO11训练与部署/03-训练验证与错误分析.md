# 训练、验证与错误分析

训练的作用是更新参数，验证的作用是暴露模型在哪些样本上失败。只保留一张 mAP 曲线，无法判断下一轮应该补数据、修标签、改阈值还是换模型。

以下命令都从教学脚本目录运行：

```powershell
Set-Location 配套资源\示例代码\yolo11
```

## 1. 先做冒烟训练

正式训练前先检查 [`classes.txt`](../../配套资源/示例代码/yolo11/classes.txt)、[`data.yaml`](../../配套资源/示例代码/yolo11/data.yaml)和数据目录，再把 [`train.py`](../../配套资源/示例代码/yolo11/train.py) 调参区改成冒烟配置——`EPOCHS = 3`、`BATCH = 4`、`WORKERS = 0`、`NAME = "smoke"`，直接运行：

```powershell
python train.py
```

冒烟训练只验证：

- 训练、验证路径能找到图片与标签。
- 类别数量和 ID 没有越界。
- Windows 数据加载进程能启动。
- 显存和内存能够支撑当前 batch。
- 输出目录能生成参数、图表和权重。

这一步失败时先修输入，不要通过增加 epoch 或换大模型绕过错误。

## 2. 正式训练把每个取舍写进调参区

[`train.py`](../../配套资源/示例代码/yolo11/train.py)调参区的默认值就是一组正式训练配置（`yolo11n.pt`、100 epoch、batch 16），按当次实验的取舍改完直接运行：

```powershell
python train.py
```

它把常用训练选项集中在文件开头：

- `MODEL`：`yolo11n.pt` 适合先建立基线；模型变大通常会增加训练与板端计算成本。
- `IMGSZ`：训练默认 640。Ultralytics 会保持宽高比并填充到训练尺寸，不等于原图必须提前拉伸成 640×640。
- `BATCH`：主要受显存限制。显存不足先减小它。
- `WORKERS`：Windows 首次使用 0，跑通后再增加。
- `CACHE`：`"ram"` 以系统内存换读取速度，`"disk"` 使用磁盘缓存，`"none"` 不缓存。
- `OPTIMIZER`：默认 `"auto"`；只有要做对照实验时再显式选择 SGD 等优化器。
- `CLOSE_MOSAIC`：最后若干 epoch 关闭 mosaic；配套默认值为 10。
- `TIME_HOURS`：以小时限制训练时长。启用它时要在实验记录中说明训练可能未跑满 `EPOCHS`。
- `SAVE_PERIOD`：长时间训练时按固定 epoch 保存中间权重，默认 `-1` 不额外周期保存。

训练配置应从数据规模、显存、内存和训练时间开始确定。每次实验都把当次调参区的取值保存到记录中，避免把设备相关的参数误当成通用配置。

## 3. 新训练与续训不能混淆

正常新实验从官方预训练权重或明确的模型配置开始，保持 `RESUME = False`。只有训练确实中断，并且要恢复优化器、学习率调度器和 epoch 状态时，才把调参区改成：

```python
MODEL  = r"runs\train\baseline\weights\last.pt"   # 该实验的 last.pt
RESUME = True
```

然后直接运行 `python train.py`。不要用 `best.pt` 续训代替 `last.pt`。如果目的是拿旧权重在新数据上继续微调，那是一次新训练，应加载权重但保持 `RESUME = False`，并给新的 `NAME`。

Ultralytics 官方[训练模式文档](https://docs.ultralytics.com/modes/train/)说明，真正的 resume 会恢复检查点中的优化器、调度器、epoch 和数据集配置。版本升级后参数含义可能变化，长训练前先核对当前文档。

## 4. 先认清训练目录里的文件

以 `PROJECT = "runs/train"`、`NAME = "baseline"` 为例：

```text
runs/train/baseline/
├── args.yaml
├── results.csv
├── results.png
├── confusion_matrix.png
├── PR_curve.png
├── train_batch*.jpg
├── val_batch*_labels.jpg
├── val_batch*_pred.jpg
└── weights/
    ├── last.pt
    └── best.pt
```

- `args.yaml` 证明这次到底用了什么参数。
- `train_batch*.jpg` 用来发现标签、增强和图片方向是否异常。
- `val_batch*_labels.jpg` 与 `val_batch*_pred.jpg` 适合并排看真值和预测。
- `last.pt` 是最后一个 epoch 的状态，常用于续训。
- `best.pt` 是按验证表现选出的权重，通常用于独立验证与导出。

不同 Ultralytics 版本的文件名可能调整，以实际输出为准。

## 5. 独立运行验证

打开 [`validate.py`](../../配套资源/示例代码/yolo11/validate.py)，把调参区指向要验证的权重和划分（默认就是 `baseline` 的 `best.pt` 和 `val` 划分），然后直接运行：

```powershell
python validate.py
```

[`validate.py`](../../配套资源/示例代码/yolo11/validate.py)会打印 mAP50、mAP75、mAP50-95，并保留混淆矩阵和预测图。这里的 `IOU` 是验证推理时非极大值抑制使用的 IoU 阈值，不是把 mAP 固定在某一个 IoU 上；不要把两个概念混在一起。

指标可以这样读：

- Precision 低：预测出来的框中误检较多，重点看哪些背景或相似类别被当成目标。
- Recall 低：真实目标没有被找全，重点看小目标、遮挡、极端亮度和训练集未覆盖的视角。
- mAP50 与 mAP50-95 差距大：模型可能能找到目标，但框的位置或大小不够稳定。
- 混淆矩阵类间错误多：先查类别定义与标注一致性，再考虑是否需要更多区分性样本。

数值是定位入口，不是结论。验证集太像训练集、漏标严重或类别极不均衡时，指标本身也会误导。

## 6. 用固定图片和摄像头复现错误

对测试目录保存预测结果（[`predict.py`](../../配套资源/示例代码/yolo11/predict.py)调参区默认 `SOURCE = "dataset/images/test"`、`SAVE = True`）：

```powershell
python predict.py
```

打开电脑摄像头实时检查（把调参区改成 `SOURCE = "0"`、`SHOW = True`、`SAVE = False`）：

```powershell
python predict.py
```

[`predict.py`](../../配套资源/示例代码/yolo11/predict.py)用于在真实画面中检查框、类别和置信度。模型路径、摄像头编号、阈值和设备均由参数指定；脚本会打印归一化 `xywh`，便于与标签和板端输出比较。

固定图片用于复现实验，摄像头用于发现现场分布差异。只做摄像头演示而不保存失败画面，下一轮很难判断修改是否真的解决了问题。

## 7. 错误分析按样本分组

每轮至少建立四组失败样本：

1. 漏检：真实目标没有框。
2. 误检：背景或非目标被框出。
3. 类别错误：位置基本正确但类别错。
4. 定位错误：框过松、过紧、偏移或重复框。

然后为每组继续按场景切分，例如小目标、遮挡、反光、画面边缘、特定背景。只有错误在某个条件下重复出现，才有理由把它归因到数据覆盖或标注规则；单张异常图不足以概括模型机制。

对应动作应尽量单一：

- 数据没覆盖：补同类场景，并保持验证来源独立。
- 标签漏框或框法不一致：修标注主版本，重新导出数据版本。
- 阈值导致取舍不合适：在固定验证集上比较，不修改训练数据。
- 模型容量不足或板端太慢：在同一数据版本上比较模型，避免同时换数据。

## 8. 每轮保存可复查记录

```text
实验名称：baseline
代码与环境：Ultralytics/PyTorch 版本，GPU
数据版本：来源视频、类别顺序、train/val/test 数量
训练参数：调参区当次取值
唯一变化：本轮只改了什么
指标：mAP50、mAP50-95、Precision、Recall
失败样本：文件名、错误类型、共同场景
判断依据：哪些图片支持这个判断
下一步：补数据 / 改标注 / 调阈值 / 换模型
```

一次改变多种因素，结果上涨后也无法知道哪一步有效。下一轮开始前先复制上一轮记录，再只改一个主要变量。
