# 03：YOLO11 训练、量化与 MaixCAM Pro 部署

这一阶段不以“训练出一个 `best.pt`”为终点，而是完成一条能定位问题的数据流：原始画面经过标注、划分、训练和验证，导出为 ONNX，再转换成 MaixCAM Pro 使用的 `.mud + .cvimodel`。如果 PC 与板端结果不同，应能判断差异发生在数据、模型、预处理、转换还是板端程序。本文内容参考[教你从零开始在MaixCAM上部署自己本地训练的Yolov5模型](https://blog.csdn.net/m0_75041317?type=blog)专栏的五篇文章，建议一起阅读。

## 为什么选择 YOLO

重要原因是在2026年这个时间点 YOLO 依旧是视觉识别最具代表性的选择。虽然现在已经涌现了很多的视觉模型，如 VLX-seek 等模型现在依旧是大模型刚开始的阶段，并且我们最终要进行边缘部署，总的来说比YOLO快的没有YOLO准，比YOLO准确的没有YOLO快，所以可能大家都说比YOLO强，但是工业里依旧全是YOLO，未来YOLO可能会被淘汰的情况我们这里不做探讨。

## 什么时候需要 YOLO11

传统视觉依赖人写出颜色、形状、轮廓等规则。当背景、角度、遮挡和目标外观变化使固定规则越来越长，仍有大量互相冲突的例外时，目标检测模型才值得加入。它把部分“手写规则”的工作换成了数据采集、标注一致性、训练验证和部署测试。

如果目标颜色与几何特征稳定，传统视觉通常更容易解释和部署。数据太少、标注互相矛盾或板端速度不满足任务时，单纯换一个更大的模型不会解决根因。

## 本阶段的学习闭环

```text
视频抽帧
→ EasyData 标注并导出 Pascal VOC
→ VOC 坐标转换为 YOLO 归一化标签
→ 保留空背景图并划分 train/val/test
→ 训练、续训、验证和摄像头检查
→ 导出固定 320×224 的 ONNX (可以按个人情况切换)
→ 准备量化图片并转换板端模型
```

配套脚本把输入、输出和训练选项集中在每个脚本开头的调参区，改完直接运行；数据处理步骤只会复制源图片和标签。完整步骤见[YOLO11 教学脚本](../../配套资源/示例代码/yolo11/README.md)。

### 1. 先确认训练环境

### 2. 把数据做成可检查的输入

[数据准备](02-数据准备.md)是本阶段最重要的一篇。它从采集方案开始，完整说明 EasyData 的在线标注、智能标注、数据增强和导出，再连接到下面四个脚本：

这一环节的产物不是“很多图片”，而是一份类别定义稳定、每张图都能追溯来源、标签能通过检查、验证集与训练集没有近重复画面的数据集。

### 3. 训练之后必须看错误样本

[训练、验证与错误分析](03-训练验证与错误分析.md)连接[训练脚本](../../配套资源/示例代码/yolo11/train.py)、[验证脚本](../../配套资源/示例代码/yolo11/validate.py)和[预测脚本](../../配套资源/示例代码/yolo11/predict.py)。训练指标只负责提示问题发生在哪一类样本；最终仍要打开漏检、误检、类别错误和框偏移的图片，判断下一轮应补数据、改标签还是改配置。

### 4. 用同一批图片贯穿导出与上板

[ONNX、量化与部署](04-ONNX量化与部署.md)从[ONNX 导出脚本](../../配套资源/示例代码/yolo11/export_onnx.py)和[量化图片准备脚本](../../配套资源/示例代码/yolo11/prepare_quant_images.py)开始，解释 `.pt → .onnx → .cvimodel + .mud` 的文件关系，最后连接到[板端推理示例](../../配套资源/示例代码/maixpy/yolo11_infer.py)。

部署验收至少要包含一组固定图片的 PC/板端对照。模型能加载、画面能显示，都不能单独证明转换正确。

## 四层产物不要混在一起

- 原始素材：视频和未经标注的图片，保留不动。
- 标注主版本：人工确认后的图片与 VOC/YOLO 标签，是之后所有实验的依据。
- 训练产物：`runs` 下的配置、曲线、错误样本、`last.pt` 和 `best.pt`。
- 部署产物：固定输入的 ONNX、量化图片、`.mud`、`.cvimodel` 和板端验证记录。

分层保存的意义是出现问题时能回退。比如验证集类别错位，应先查 `classes.txt`、`data.yaml` 和标签，不要直接重做模型转换。

## 做到什么算过关

1. 能说明自己的类别定义和标注规则，并找出一张正样本、一张负样本和一张边界样本。
2. 能运行数据检查，解释空标签、类别越界、图片与标签不配对分别意味着什么。
3. 能完成一次小规模训练和独立验证，保存至少一组误检与漏检并提出下一步动作。
4. 能从同一个 `best.pt` 导出固定输入 ONNX，核对类别和预处理，再生成匹配的 `.mud + .cvimodel`。
5. 能用同一张图片比较 PC 与 MaixCAM Pro 的框、类别和置信度，并准确记录尚未验证的部分。

识别框还只是像素坐标。下一阶段继续学习[坐标转换、标定与现场调试](../04-坐标转换、标定与现场调试/README.md)。
