# 像素到机械坐标标定

## 先定义两个坐标系

像素坐标记为 `(u, v)`：原点在图像左上角，`u` 向右，`v` 向下，单位是像素。

机械坐标记为 `(x, y)`：原点和正方向由机械系统定义，单位是毫米。联调前必须让双方把原点、正方向和安全范围画在同一张图上。

## 2026 项目使用的映射

```text
x = offset_x + x_sign × (v - center_v) / px_per_mm
y = offset_y + y_sign × (u - center_u) / px_per_mm
```

- `(center_u, center_v)`：图像参考中心。
- `(offset_x, offset_y)`：该像素中心对应的机械坐标。
- `px_per_mm`：每毫米对应多少像素。
- `x_sign`、`y_sign`：只能取 `1` 或 `-1`，处理轴方向翻转。
- `v → x`、`u → y`：轴交换，表示安装关系中包含约 90° 旋转。

例如中心为 `(320, 224)`，中心对应机械位置 `(271, 221)`，比例为 `2 px/mm`，方向为 `(-1, 1)`。像素点 `(340, 244)` 得到：

```text
x = 271 - (244 - 224) / 2 = 261 mm
y = 221 + (340 - 320) / 2 = 231 mm
```

## 实际标定顺序

1. 固定相机、工作平面、分辨率、裁剪和镜头矫正参数。
2. 检测已知边长 30 mm 的方块。
3. 取检测到的像素边长，计算 `px_per_mm = side_px / 30`。
4. 选择图像中心，测量该点对应的机械坐标作为 `robot_offset`。
5. 分别测试图像上、下、左、右的点，判断 `x_sign`、`y_sign`。
6. 使用多个已知点验证预测坐标，记录残差。

这里的实际代码用多点做校验，不是通过多点拟合出一套任意旋转矩阵。

## 怎么看残差

对第 `i` 个已知点：

```text
dx_i = predicted_x_i - measured_x_i
dy_i = predicted_y_i - measured_y_i
error_i = sqrt(dx_i² + dy_i²)
RMSE = sqrt(mean(error_i²))
```

- 所有点偏移方向接近：优先检查 `robot_offset`。
- 误差随离中心距离增大：检查 `px_per_mm`。
- 左右或上下镜像：检查方向符号与轴交换。
- 不同区域误差方向明显变化：简化模型可能不够，应检查镜头畸变（判断与矫正方式见[相机畸变矫正](02-相机畸变矫正.md)）、平面倾斜，并考虑仿射或单应性标定。

打开 [coordinate_validator.py](../../配套资源/示例代码/通信与gcode/coordinate_validator.py)，它按"读入已知点 → 畸变矫正（可选）→ 像素/机械映射 → 残差汇总"四步实现本篇公式，每一步的推导写在对应函数的注释里。把调参区的 `POINTS_FILE`、畸变参数（`DIST_K1`、`DIST_K2`，置 0 即关闭这一步）和映射参数（`PX_PER_MM`、`CENTER_U`、`CENTER_V`、`OFFSET_X`、`OFFSET_Y`、`X_SIGN`、`Y_SIGN`）换成自己的标定值，然后直接运行：

```powershell
python 配套资源\示例代码\通信与gcode\coordinate_validator.py
```

示例目录带两份点表：`sample_points.csv` 与公式完全一致，误差应为 0；`sample_points_distorted.csv` 预先套上了 `k1=-3e-7` 的桶形畸变，把 `POINTS_FILE` 指向它就能在不开相机的情况下复现"中心准、边缘放射状渐偏"，再把 `DIST_K1` 设为 `-3e-7` 验证矫正步骤把误差收回约 0。

## 哪些变化后必须重新标定

- 摄像头分辨率或缩放方式改变。
- 修改裁剪区域或 ROI 原点。
- 开启、关闭或调整镜头畸变矫正。
- 相机位置、角度或高度改变。
- 工件所在平面高度改变。
- 机械原点、轴方向或安装关系改变。

不要只修改公式中的某个常数继续使用旧结果。重新拍标定图、计算比例、确认方向，并再次跑已知点校验。
