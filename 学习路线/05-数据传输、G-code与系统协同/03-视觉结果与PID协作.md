# 什么是 PID——闭环控制入门

电赛视觉题做到最后，"看"和"动"总要接在一起：视觉算出偏差，机械去纠这个偏差。做视觉和做控制的同学需要一套共同的语言，PID 就是这套语言里最常用的词。这一篇回答三个问题：为什么需要闭环控制；PID 解决了闭环里的哪个问题；它该怎么理解、怎么学。它不负责教你调出一组能用的参数——那依赖具体机械，是控制端的事。

## 为什么需要闭环控制

想让小车前进 1 米，最直接的做法是开环：先测好"满 PWM 跑 1 秒大约走多远"，之后每次都给固定的 1 秒。第一次可能正好停在 1 米；换一块电压偏低的电池、换一张摩擦更大的桌面、左右轮有一点装配偏差，它就不停在那里了。开环只下达命令、不看结果，它相信预测——只要执行条件和校准时一模一样，结果就对；条件一变，误差没有任何机会被纠正。

对比一件每个人都会做的事：调淋浴水温。没有人先计算热水器功率和水管长度再拧阀门，而是拧一点、用手试、偏热就往回拧，每一步都是"测一下，根据差多少再调一点"。这就是闭环：拿目标值和测量值不断比较，按误差修正输出。它有三个要素——目标值、测量值、按误差算出来的修正量。

开环不是错的，要看场合：

- 动作固定、坐标已经过标定校验、执行过程没有持续扰动时，按顺序执行动作就够了，见[G-code 视觉侧接口](02-G-code视觉侧接口.md)。
- 目标在动、扰动持续存在、需要不断对准时（巡线、跟踪、云台跟拍），就必须闭环。

一句话区分：开环相信预测，闭环相信测量。

## PID 解决了闭环里的哪个问题

闭环只规定了"要按误差不断修正"，没有回答一个更具体的问题：误差是 5 的时候，输出到底该给多大？把误差翻译成输出的规则，叫控制器。PID 是其中用得最多的一个：

```text
误差 error = 目标值 - 测量值
输出 output = Kp × error + Ki × 误差累积 + Kd × 误差变化
```

三个加数分别看现在、过去和趋势：

- P（比例）看现在的误差：差多少就纠多少，误差大力度大，误差归零力度归零。它提供即时反应，但有两个毛病。一是有惯性的系统会冲过目标来回摆——误差为零的那一刻修正力也为零，可速度还在，于是冲过头、反向再纠。二是需要持续输出才能平衡的场合（爬坡、带负载）会停在离目标差一小段的地方，因为"差的那一小段"正好产生顶住外力所需的输出。这一小段叫稳态误差。
- I（积分）看过去的误差：把每一周期的误差累积起来，只要误差不归零，累积就一直变大、输出一直加力，直到把残留的那一小段顶掉。代价是误差长期同号时累积过大，目标突变后来不及释放，系统冲过头；这个现象叫积分饱和。
- D（微分）看误差的变化趋势：误差在快速缩小，说明正在接近目标，就提前收力。它像减震器，专门抑制来回摆。代价是放大噪声——误差里的每一次抖动都会被放大进输出，而视觉检测的坐标是逐帧跳动的。

| 项  | 看的是         | 解决什么               | 代价                       |
| --- | -------------- | ---------------------- | -------------------------- |
| P   | 现在的误差     | 立即响应，误差大纠正猛 | 有惯性时振荡；存在稳态误差 |
| I   | 过去的误差累积 | 消掉稳态误差           | 累积过大冲过头（积分饱和） |
| D   | 误差变化的趋势 | 提前收力，抑制振荡     | 放大测量噪声               |

一个力学类比：P 像弹簧，拉得越开往回拉得越狠；D 像减震器，动得越快阻力越大；I 像一直顶住恒定外力的那只手——弹簧劲不够时，它一点点加力直到顶住为止。

PID 不是唯一的控制器，也不保证任何系统都能被它调稳；但在电机调速、温度、云台、循迹这类问题上，它是默认起点，也是理解更复杂控制器的参照系。

## 一个可以动手的最小实验

参数听别人讲一万遍，不如自己改一次看曲线。下面是一个二十多行的仿真：一辆只能被推着走的小车，控制器输出推力，推力改变速度，速度积分成位置，目标是 100。只用标准库，直接运行：

```python
# —— 调参区：每次只改一个数，直接运行 ——
KP = 0.5    # 比例：现在的误差
KI = 0.0    # 积分：误差的逐周期累积
KD = 0.0    # 微分：误差的变化量
WIND = 0.0  # 恒定扰动：相当于地面带一点坡度

TARGET, CYCLES = 100.0, 80

x, v, integral, prev_err = 0.0, 0.0, 0.0, 0.0
for i in range(CYCLES):
    err = TARGET - x
    integral += err
    deriv = err - prev_err
    prev_err = err
    out = KP * err + KI * integral + KD * deriv
    v += 0.1 * out + WIND   # 推力改变速度；WIND 是恒定外力
    x += v                  # 速度积分成位置
    bar = "#" * max(0, min(60, int(x / 2)))
    print(f"{i:3d}  err={err:8.2f}  x={x:8.2f}  {bar}")
```

按顺序做四个实验，现象都来自这段代码的实际运行：

1. 默认参数（只有 P）：小车在 0 和 200 之间来回摆，停不下来。误差为零时修正力也为零，但速度还在——这就是"只有 P"在有惯性系统上的典型形态。
2. 把 KD 改成 2：误差缩小过程中 D 项往回拉，像装了减震器，小车冲过一次、回摆一次后停在 100。
3. 保持 KD=2，把 WIND 改成 0.5：小车稳定停在 110。恒定外力需要持续输出顶着，纯比例只能"停在还有误差的地方"用 P 项顶住它——这多出来的 10 就是稳态误差。
4. 再把 KI 改成 0.02：残留误差逐周期累积、慢慢加力，小车回到 100 附近并最终停在那里（约 400 周期后误差小于 0.01）。

每次只改一个参数，先预测曲线会怎么变，再运行对照。预测错的那一次，就是理解长出来的地方。

## 调参的通用顺序和常见症状

通用做法是：从 Kp=0 开始加大 P，到系统刚好不振荡再退回一点；然后少量加 I，消掉稳态误差就停；最后用 D 压超调和振荡。每一步把目标值、测量值和输出记下来画在同一张图上——PID 调的是曲线，不是感觉。

调不出来时，先对着现象找方向（常见原因，不是定律）：

| 现象               | 常见原因                 |
| ------------------ | ------------------------ |
| 停在离目标差一小段 | I 缺失或太小             |
| 来回振荡收不住     | P 太大，或缺 D           |
| 冲过目标再慢慢回来 | I 太大                   |
| 输出抖动剧烈       | D 太大，或测量本身噪声大 |

仿真和真实系统最大的差别：仿真里参数只是数字，真实系统里参数和机械绑在一起。电池电压下降、负载变化、重心改变，都会让昨天调好的参数今天变差。PID 参数没有"正确值"，只有"当前这台机械上曲线可接受"，这也是为什么调参属于整机调试，而不是能从别人那里抄来的常数。

## 视觉在闭环里的位置

在视觉题的闭环里，相机加检测就是测量本身：控制器算误差用的那个数，是视觉给出来的。测量不好，控制器再好也没用——D 项会放大检测噪声，传输延迟让系统追的是"过去的目标"。所以视觉侧交测量时，四件事要先和控制端约定：

- 单位：像素、毫米还是角度。机械在毫米坐标运行时，先经过[坐标标定](../04-坐标转换、标定与现场调试/01-坐标标定.md)。
- 节奏：定周期发送，让控制端知道相邻测量的时间间隔。
- 新鲜度：带上时间戳或序号，控制端才能丢弃过旧的数据。
- 有效性：无目标、低置信度时明确告知，而不是停在最后一个坐标上装作正常。

## 边界

本仓库不提供电机 PID 参数或下位机实现。想深入控制本身——离散化、串级控制、滤波器——那是自动控制原理的课程内容，找教材和队里做控制的同学，不属于这条视觉路线。同时为了得到标准可用的PID的参数有很多的自动化计算算法，如：拓竹打印机自动调平、Klipper固件中的自动校准温度PID等实际使用场景，甚至将串口的输入和输出都接到codex上让AI自己不断调整，这里只作为启示，详细实现可以自己深入探索。
