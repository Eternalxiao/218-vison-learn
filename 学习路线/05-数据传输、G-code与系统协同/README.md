# 05：数据传输、G-code 与系统协同

## 为什么最后才发送动作

这一关接收的是已经经过定位、标定和现场验证的结果。视觉端要把类别、坐标、角度或有效状态明确地交给接收端；G-code 只在坐标可信、执行端支持且安全条件满足时才生成。PID 放在最后作为队内科普：从为什么需要闭环讲起，讲清 P、I、D 各自解决什么问题，以及视觉作为测量来源要交付什么，不替代控制端的实现。

## 1. 先约定数据，再写串口

字段名称、类型、单位、坐标原点、正方向、无目标状态和发送频率应先写进接口约定。字符串、JSON 和二进制帧各有用途；半包和粘包必须用缓冲区测试。见[串口数据格式](01-串口数据格式.md)。

## 2. 什么时候可以生成 G-code

G-code 是数控机床和 3D 打印机固件沿用下来的运动命令集，接收端要有解释器（现成固件或控制端自写解析器）才能执行。它适合执行已经确定的坐标与动作顺序，不会自动补上坐标标定、避障、状态反馈或急停。命令含义、完整动作翻译、分块发送节奏和项目专用命令见[G-code 视觉侧接口](02-G-code视觉侧接口.md)。先用日志核对命令，再连真实机械。

## 3. PID：闭环控制入门

这一篇回答三个问题：为什么需要闭环控制，PID 解决了闭环里的哪个问题，怎么理解它——包括一个改三个参数就能看曲线的小仿真。最后说明视觉在闭环里是测量来源，交付测量时要约定单位、节奏、新鲜度和有效性。见[什么是 PID](03-视觉结果与PID协作.md)。

## 闯关项目

1. 把同一个检测结果编码成字符串、JSON 和二进制帧，再用分段输入检查半包和粘包。
2. 从一份已通过已知点校验的机械坐标生成 G-code，只保存日志并人工检查命令顺序。
3. 画出目标值、视觉测量值、误差、`valid` 状态和控制输出的数据流，说明无目标时接收端应看到什么。

## 做到什么算过关

你能和控制同学共同写出没有歧义的接口；在视觉结果不可信时不发送动作；在需要闭环时，清楚视觉侧交付的是测量及其有效状态，而不是直接控制电机。
