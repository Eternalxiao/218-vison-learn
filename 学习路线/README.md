# 电赛视觉学习路线

这条路线的目标不是让所有人都学成同一种样子，而是让你先完成视觉任务的最小闭环，再根据队伍情况和分工决定学到什么程度，我个人将其粗略的分为三类。

## 先选择你的目标

这三类不是能力高低，也不是一开始就不能改变的身份，而是为达到同一个目标学习深度的不同。多数同学都会先以产品使用者的方式跑通第一个闭环；当你开始想知道“为什么这个阈值有效”，期望自己设计解决方案时转向视觉软件方向；当使用的现成产品（主要是 MaixCAM Pro）已经不够支撑自己的目标、想处理设备和系统问题时，再深入到嵌入式应用方向。

选择时先问自己：自己的目标是什么，是平时简单、了解浅浅学习，比赛前几周配合队友，赛中坐等开源，对自己整体要求不高比较佛系；还是想自己学习设计视觉方案，学习不同视觉处理方式，形成自己的视觉设计思路；或者是作为一个“电信人才“未来期望深入学习嵌入式期望了解视觉模块在一整套设备的定位？不是每个同学都要精通视觉甚至不是所有同学上大学是为了“认真学习”，所以下面每一类都给出负责范围和停止范围，避免把时间花在暂时不需要的内容上。

### 产品使用者：把已有方案配置、部署和适配

**适合谁。** 你当前最优先的目标是让队伍有一个能工作的视觉模块让自己队伍的作品可以跑起来。你可能拿到的是已经开源的代码、视觉模型或队内方案，需要把它放到自己的 MaixCAM Pro 上，适配现场画面，并把结果交给控制同学。这个方向不是“只会点按钮”：你需要能读懂关键配置和关键代码，做有适配和修改。

**你最后要交付什么。** 一套可重复启动的并且解决问题的视觉”黑盒“，以及一份能和队友配合起来的运行说明：模型或脚本在哪里、摄像头分辨率和 ROI 是什么、阈值或置信度如何改、类别编号代表什么、串口会发出哪些字段。现场出问题时，你能定位问题知道修改哪部分，而不是只说“它刚才没识别到”。

**优先学什么。** 按这个顺序完成即可：

1. 完成[第 0 关](00-认识电赛视觉/README.md)，能把问题拆为“采到什么图—程序做了什么—发出了什么结果”。
2. 完成[第 1 关](01-MaixCAM-Pro与MaixPy/README.md)，会连接设备、运行脚本、保存画面、画出检测结果，并修改分辨率、ROI、颜色阈值或一个检测参数。
3. 阅读[第 3 关](03-YOLO11训练与部署/README.md)的完整链路，但优先完成[ONNX、量化与部署](03-YOLO11训练与部署/04-ONNX量化与部署.md)：会核对模型对、模型路径、输入尺寸、类别和置信度，而不是急着从零训练大数据集。
4. 需要输出毫米坐标时，完成[第 4 关](04-坐标转换、标定与现场调试/README.md)：会做已知点校验、判断畸变是否影响坐标转换，并在界面中查看输入与结果。
5. 完成[第 5 关](05-数据传输、G-code与系统协同/README.md)的接口部分：会修改字符串、JSON 或已有帧格式中的字段，并用日志或回环确认接收方读到的内容与发送方一致。

[第 2 关](02-OpenCV传统视觉/README.md)对你不是必修的算法课，但应至少使用一次视觉流程调试器或中间图，理解“阈值改错时图像会怎样变化”。这样你修改参数时有观察依据。

**暂时不要求什么。** 不要求先推导形态学、卷积或神经网络的数学原理；不要求先从零写传统视觉算法；不要求理解下位机芯片、RTOS、电机和控制原理。你要理解的是视觉模块的输入、配置、输出和错误现象，而不是替所有队友承担所有方向。

**必须会怎样排障。** 每次异常的原因是什么如何定位，再按顺序判断：画面是否正常采到；目标在原图中是否清楚；检测结果是否已经画在图上；模型路径、类别、阈值或置信度是否正确；最后才检查发送内容。这样能区分问题在采图、识别还是传输。一次只修改一组参数；不能靠同时改阈值、模型和串口格式“碰运气”。

**怎样算完成，何时进阶。** 让另一位同学按你的说明重新启动程序；他能改一个阈值、模型路径或输出字段，并复现你保存的一次正常结果，就说明这个模块已经可交接。当你`不再满足于“参数调到能用”，而开始想为新目标设计特征、解释失败样本或训练自己的模型时，转入下一阶段视觉软件方向。`

### 视觉软件方向：自己设计、解释和验证视觉方案

**适合谁。** 你希望负责视觉代码本身但不准备深入学习嵌入式硬件设计，只期望做一个”软工人“：面对一个新目标，能够判断它适合颜色、几何、轮廓等传统特征，还是值得采集数据训练 YOLO；能够解释每个处理步骤，而不是只把现成程序跑起来。这里的“软件”指图像和数据处理，不等于要承担下位机硬件开发。只建议网工、软工或者不准备走嵌入式方向的同学在这一步就停止。

**你最后要交付什么。** 除了可运行程序，还应有一条能解释的处理链：输入图片、每一步中间结果、最终决策依据，以及失败的原因。涉及机械动作时，还要交付像素到机械坐标的标定参数，而不是只给一个未经检查的固定公式。你的队友应能从这些材料知道程序为什么这样判断、换场地后从哪里开始调，完整学完这一步你已经是一个合格的电赛视觉手。

**需要学到哪里。** 六个阶段都应完成，建议严格按顺序：

1. 在[第 0 关](00-认识电赛视觉/README.md)建立图像、颜色空间、ROI、特征和检测结果的共同语言。
2. 在[第 1 关](01-MaixCAM-Pro与MaixPy/README.md)先用 MaixPy 封装函数跑通实时任务，理解设备端输入、显示和调试标注。
3. 把[第 2 关](02-OpenCV传统视觉/README.md)作为核心：先用[滤波、形态学与轮廓](02-OpenCV传统视觉/01-滤波、形态学与轮廓.md)理解处理链，再用[MaixPy 图像处理接口](02-OpenCV传统视觉/02-MaixPy图像处理接口.md)把已经确认的步骤迁移到 MaixCAM Pro。
4. 在[第 3 关](03-YOLO11训练与部署/README.md)完成数据清理、划分、训练、验证和错误样本分析，知道 Precision、Recall、IoU 和 mAP 各自提示什么问题；再进入 ONNX、量化和板端部署。
5. 在[第 4 关](04-坐标转换、标定与现场调试/README.md)完成坐标转换、标定、已知点校验、畸变检查和 GUI 调试，确保毫米坐标在整个视觉管线中可信。
6. 在[第 5 关](05-数据传输、G-code与系统协同/README.md)完成字段约定、拆包粘包测试和 G-code 模拟输出，确保可信结果能被系统正确使用。

**暂时不要求什么。** 你需要会使用串口接口并和控制同学共同确定数据格式，但不必在本项目里学习看门狗、引脚配置、驱动编写、RTOS 或电机控制。你也不必为了“更底层”而立刻重写已有 MaixPy 功能；先证明当前处理链的正确性和速度，再决定是否需要优化。

**必须会怎样排障。** 你要能沿数据流排查，而不是只看最后的识别框：检查颜色空间和图像格式是否一致；检查滤波、阈值和形态学每一步丢掉了什么；检查轮廓或检测框为什么被筛掉；检查训练集、验证集和错误样本是否暴露了场景变化；检查 PC 与板端的输入尺寸、预处理、量化和类别是否一致；对每一次重要选择，至少保留一个可复现的输入和一个可解释的输出。

**怎样算完成，何时进阶。** 面对一个没有现成答案的简单目标，你能先提出特征或数据方案，做出中间图或验证记录，根据失败现象修改一处环节，并说明为什么这样改；最后把结果稳定交给接口层，就说明具备了视觉软件方向的基础。这时候你几乎可以解决历年电赛控制赛题的全部视觉问题（默认可以找到并且复现对应的识别分析算法，如拼图算法、区分重叠目标的几何算法和图像算法），但是若瓶颈开始来自设备资源、编译部署、相机驱动或多个程序协同，而不是你视觉代码、方案、算法本身，下一步再进入嵌入式应用方向。

### 嵌入式应用方向：让视觉模块成为设备中的一部分

**适合谁。** 你已经能完成视觉侧闭环，但希望继续负责设备上的运行环境和系统协同。例如，你想理解 MaixCAM 这样的小的linux系统上程序如何启动和占用资源、怎样用 C/C++ 处理性能需求、怎样跨平台编译和部署，或怎样把相机、视觉程序和控制系统组织成稳定的整体。

**这个方向新增的负责范围。** 视觉软件方向主要对“图像进来后如何得出结果”负责；嵌入式应用方向还要对“程序如何在设备上长期、稳定地运行”，设备每个部分如何拆解替换负责。后续可以学习 Linux 基础、C/C++、进程与文件管理、摄像头和设备接口、交叉编译、性能与内存分析，以及与控制方向共同进行系统联调。若确实有需求，再学习无屏幕设备、相机驱动或更深的硬件接口。

**从本项目带走什么。** 本仓库只提供你进入这条路前必须守住的视觉侧边界：图像从哪里来、检测结果包含哪些字段、坐标如何标定、畸变如何影响测量、数据帧如何定义、G-code 如何由视觉结果生成。请先完整走完六个阶段，并保留这些接口测试；以后换成 C/C++、更换相机或调整设备架构时，它们仍是联调的基准。

**暂时不在这里学什么。** 本项目不教授具体芯片选型、RTOS、下位机固件、电机驱动或控制算法，也不把任何控制器专用命令说成通用标准。这些内容要根据队伍真实硬件和负责人的分工另行学习、验证。

**必须会怎样协作和排障。** 你需要把系统问题切开：视觉侧先用保存图片和日志证明识别输出；接口侧用回环或抓包证明字段和字节顺序；控制侧再验证接收和动作。和控制同学共同维护一份字段、单位、坐标原点、轴方向、更新频率和异常处理的约定。不要在视觉结果不确定时直接归因于控制，也不要在接口未验证时让机械结构连续运动。

**怎样算进入这条路。** 当你能先独立完成一套视觉算法和接口交付，再为实际性能、部署或设备协同提出一个明确的问题，并能用日志、资源数据或接口测试复现它，你就具备了继续学习嵌入式应用的起点。这里没有“学完”的统一标准；接下来该学什么取决于你的真实设备和队伍分工。

## 学习闯关顺序

### 第 0 关：先知道视觉系统在做什么

- 入口：[认识电赛视觉](00-认识电赛视觉/README.md)
- 产物：画出“摄像头输入—图像处理—结果输出”的框图。
- 过关：能用自己的话解释像素、图像帧、颜色空间、ROI、特征和检测结果。

### 第 1 关：跑通 MaixCAM Pro

- 入口：[MaixCAM Pro 与 MaixPy](01-MaixCAM-Pro与MaixPy/README.md)
- 产物：实时画面上能够框出一个目标，显示中心坐标和 FPS。
- 过关：可以不复制整份项目，自己查 API 并改动一个关键参数。

### 第 2 关：学会设计传统视觉处理链

- 入口：[OpenCV 传统视觉](02-OpenCV传统视觉/README.md)
- 产物：原图、预处理图、二值图、形态学结果、轮廓图和最终结果。
- 过关：换一张相似场景的图片后，知道应该改哪个阶段，而不是重新乱试全部参数。

### 第 3 关：完成一次神经网络部署闭环

- 入口：[YOLO11 训练与部署](03-YOLO11训练与部署/README.md)
- 产物：自定义数据集、训练结果、错误样本记录、ONNX、量化模型和板端推理画面。
- 过关：能说明 PC 与板端效果不一致时应该检查输入尺寸、预处理、类别、量化数据和置信度中的哪一项。

### 第 4 关：让毫米级坐标转换结果可信

- 入口：[坐标转换、标定与现场调试](04-坐标转换、标定与现场调试/README.md)
- 产物：一组标定参数、已知点误差记录、畸变检查和可观察中间结果的调试界面。
- 过关：知道毫米误差来自比例、坐标映射还是镜头畸变，并能在 GUI 中定位视觉管线的失败阶段。

### 第 5 关：把可信结果交给机械系统

- 入口：[数据传输、G-code 与系统协同](05-数据传输、G-code与系统协同/README.md)
- 产物：一份字段明确的接口约定、一次编码解码回环和一段模拟 G-code。
- 过关：视觉程序连续运行时，接收方仍能区分每一帧数据并正确解释单位和坐标方向；需要持续纠偏时，能说明视觉测量怎样进入控制闭环。

## 学习时一直保留的习惯

1. 保存原始输入，不要只保存成功结果。
2. 把每一步中间图像画出来或保存下来。
3. 每次只改一类参数，并记录改动前后的现象。
4. 先验证坐标和数据格式，再连接会运动的机械结构。
5. 能用简单特征解决时先用传统视觉；目标变化复杂、类别难以手工描述时再考虑 YOLO 等神经网络的方式。
