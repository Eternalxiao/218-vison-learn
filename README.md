# TILearn：留给后来同学的电赛视觉学习路线

这是我根据两年电赛学习与实践整理的一份视觉入门资料，写给刚进入 218 实验室、准备接触电赛的学弟学妹，也欢迎实验室之外对视觉感兴趣的同学阅读、使用和补充。

你可能是从学长学姐那里听说了这个项目，也可能第一次打开 GitHub，还不知道这些文件应该怎么看。都没关系。这一页先介绍我为什么留下它、希望它能帮到你什么，以及怎样开始阅读。想先了解操作方法，可以直接看[第一次打开这个项目，应该怎么读](#第一次打开这个项目应该怎么读)。

## 为什么想把这些东西留下来

临近毕业，回头看在 218 待过的这几年，两届电赛是我成长很快、也不断发现自己不足的一段经历。整理这个项目，也是给自己做一次复盘：哪些东西真正学会了，哪些问题当时没有想清楚，又有哪些经验值得让后来的人早点知道。

以前准备电赛，我更多是在学一个个模块，觉得能识别目标、能把算法写出来，视觉这部分就准备得差不多了。第一届比赛时，我一直想先把算法做完整，再去封装功能、完善调试，结果把观察问题、适应现场环境的准备留得太晚。第二届我吸取了教训，每完成一部分就尽量封装、可视化，也提前准备了调试界面。

但当视觉、机械和控制没有及时接起来时，个人准备得再多，仍然会有许多问题直到最后才暴露。我们很晚才开始把各部分放在一起测试，通信、定位和机械细节陆续出现问题，留给反复验证和修改的时间已经很少。经历这些以后，我才更清楚地认识到：会使用模块只是起点，还要知道它在整套系统中负责什么、依赖什么，以及怎样和队友一起验证它。

我希望把这些认识连同代码和学习材料一起留下。等我毕业之后，下一位准备学视觉的同学，仍然能找到一份讲清来龙去脉的资料，而不必从零打听该学什么，也不必只对着一份旧程序猜当时的人为什么这样写。这是我想留给 218 的一份可以继续积累的学习资产。

## 希望你从这里带走什么

这份路线首先想帮你建立“架构认知”。这个词听起来有些抽象，其实就是先知道：摄像头得到一张图之后，程序怎样从中找到需要的信息，这些信息怎样变成队友能使用的数据，又怎样参与整套装置的工作。遇到问题时，能大致判断应该检查哪一部分，还需要补哪方面的知识。

围绕这件事，项目整理了 MaixCAM Pro / MaixPy、OpenCV 传统视觉、YOLO11 训练部署，以及坐标标定、现场调试和视觉侧数据交付的学习内容。你可以跟着它了解为什么学、去哪里学、怎样动手验证，并逐渐形成自己的视觉方案设计思路。

我是软件工程背景，写下来的主要是自己实践过的视觉侧经验，覆盖不了电赛所需的全部知识。几何算法、机械、控制、硬件电路等方向，还需要结合自己的兴趣和队伍需求继续学习。这份路线提供一个起点，也希望帮助你看清之后还有哪些方向可以走。

我也希望 218 能有更多各有所长的同学：有人愿意钻研视觉，有人喜欢算法、机械、控制或电路。大家在一起做小项目、练习题的过程中，逐渐知道彼此能做什么、哪些地方需要共同商量。学习视觉的人也应理解结果会被怎样使用，尽早和队友一起测试，而不是等各自觉得“全部写完了”才第一次把系统接起来。

## 第一次打开这个项目，应该怎么读

GitHub 是存放和共同维护项目的网站，这里的一份项目叫“仓库”，你可以把它理解成一套放在网上、会持续更新的资料。**你现在读的这一页就是根目录的 `README.md`，也就是整个项目的首页说明。**

`README` 可以理解为“先读我”。你会在不同文件夹里看到同名文件，它们分别介绍所在部分怎么使用，内容并不相同。`.md` 是 Markdown 文档的文件后缀；在这里，这类文件主要就是供你阅读的文章。用浏览器在 GitHub 上点开，就能看到排好版的文字和图片。第一次阅读不用先下载整个项目，也不用安装专门的软件或学会 Markdown 语法。

可以这样开始：

1. 点开[学习路线总说明](学习路线/README.md)，了解不同学习目标和整体顺序。还没有想好以后走什么方向也没关系，可以先从[认识电赛视觉](学习路线/00-认识电赛视觉/README.md)读起。
2. 进入某个阶段后，先读该文件夹的 `README.md`。它会说明这一部分要学什么，并给出正文入口。点击文章里的链接，就能进入相应内容，不需要自己在所有文件夹里挨个寻找。
3. 按阶段说明阅读专题、做练习，再对照完成标准检查。阶段文件夹前的 `00`、`01` 等是学习顺序；阶段内文章前的编号是本阶段的建议阅读顺序。忘记读到哪里时，可以回到学习路线总说明重新找到入口，也可以给正在读的页面加一个浏览器书签。

只想先认识视觉，可以直接开始读。动手运行示例时，需要逐步补齐 Python 的变量、条件、循环、函数等基础；设备和软件则跟着对应章节准备。遇到暂时不懂的名词，先记下来，结合文章中的解释和推荐资料继续学。

读到需要代码、模型或工具的地方，再跟随文中的链接打开[配套资源说明](配套资源/README.md)。教学示例适合配合文章练习；历年题目参考代码适合有了基础以后阅读思路，不保证在你的设备上直接运行。其中 2021、2023、2024 是往年题目参考代码，2025、2026 是我实际参与并留下的视觉代码。`memory/` 和以点开头的配置文件夹用于项目维护，初次学习可以先跳过。

想回头查一个知识点时，先在学习路线和对应阶段的说明中找专题；电脑浏览器里的 `Ctrl + F` 可以查找当前页面的关键词，但不会一次搜索整个项目。若你连问题该叫什么都不确定，也可以把读到的位置和困惑记下来，按下面的方法提问。

## 读不懂、发现错误，也可以参与完善

这些文字和代码来自我的学习过程，难免有讲得不清楚、考虑不周或随着工具更新而不再适用的地方。欢迎你指出问题，也欢迎把自己验证过的方法补充进来。刚开始学习的人尤其能发现：哪些地方省略了步骤，哪些词作者觉得理所当然，读者却第一次见到。

项目的 [Issues（议题）页面](https://github.com/Eternalxiao/TIlearn/issues)就是公开记录问题、建议和讨论的地方。你不需要先会改代码，也不必先学会提交代码，写清楚自己的问题就可以参与。

登录 GitHub 账号后，打开上面的链接，先看看有没有人问过相同的问题；如果没有，点击 `New issue`（新建议题），填写标题和正文，再提交。具体按钮操作也可以参考 [GitHub 的创建议题说明](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-an-issue)。

标题可以直接写“坐标标定一节的单位没有看懂”或“某篇文章的链接打不开”。正文里尽量说明：你读的是哪篇文章、卡在哪一段、已经尝试过什么、希望补充怎样的解释。如果是运行问题，再附上设备、相关软件版本、报错或截图；如果只是文章没读懂，用自己的话描述即可。

以后解决了问题，也欢迎在原议题里补上方法和验证结果。这样一次答疑就能留下来，遇到同样问题的人也能找到。你整理了新的视觉案例、发现更清楚的讲法，或者想帮忙维护某一部分，也可以先开一个议题一起讨论。

## 也请把它介绍给下一届

这份资料能不能真正帮到后来的人，很大程度上取决于他们是否知道它的存在。如果你觉得其中有些内容有用，希望在新同学加入 218、第一次问起“视觉该怎么学”时，你能把[项目首页](https://github.com/Eternalxiao/TIlearn)介绍给他，带他点开第一篇文章，讲讲自己当时是怎么开始的。实验室里的口口相传，可以从这样一件小事开始。实验室之外的同学也欢迎把它分享给有需要的人。

等你有了自己的实践，也希望你能留下一点东西：一处更清楚的解释、一个能复现的小例子、一段调试记录，或者一篇讲明白问题经过的复盘。你在控制、机械或电路方向积累的经验，也可以整理成自己的资料，介绍给下一届，让实验室不同方向的积累慢慢丰富起来。

感谢齐老师这些年的指导，也感谢一起在 218 学习、讨论和做项目的同学。临近毕业，我能先留下的是自己走过的这一段。希望以后你再把这份资料交给学弟学妹时，里面也已经有了你补充的经验。
